# 崩溃分析与修复记录（2026-10-25 / 26）

对象：《霍格沃茨之遗》Steam 版 buildid 20773316 + UE4SS `3.0.1-201-g7cd4e3f` + SpellUnlocker v1.4 / v1.5 / v1.6

> 本文是一次真实的「用 minidump + 日志定位游戏 Mod 崩溃」的完整记录，方法论可复用到其他 UE4 + UE4SS 的 Mod 调试。
> 仓库不带任何 dmp / 日志文件（含玩家信息与游戏内存），只保留结论与复现方式。

---

## 一、三次崩溃的原始证据

| # | 崩溃场景 | 异常码 | 出错地址 | 读目标 | 崩溃线程栈特征 |
|---|---|---|---|---|---|
| 1 | 读档进世界 | `0xC0000005` | `UE4SS.dll + 0x6C328F` | 野指针 | 全在 UE4SS.dll / ntdll / ucrtbase |
| 2 | 读档进世界 | `0xC0000005` | `UE4SS.dll + 0x6C328F` | 野指针 | 同上 |
| 3 | 进入地下城 `Cav_Dungeon_12` | `0xC0000005` | `UE4SS.dll + 0x6C328F` | 野指针 | 同上 |

三次同一地址 → 确定性代码路径，不是随机崩溃。
第 3 次用 `tools/parse_minidump.py` 解析：**崩溃线程栈里没有任何 `HogwartsLegacy.exe` 帧**
→ 崩溃线程**不是游戏线程**，而是 UE4SS 内部线程（Lua 异步回调线程）。

## 二、两个独立 Bug

### Bug A（v1.4，修于 v1.5 / v1.6）：hook 内做 FName→string 转换

`UE4SS.log` 抓到决定性 traceback：

```
[DelayedAction] No overload found for function 'FName'.
stack traceback:
    [C]: in method 'ToString'
    main.lua: in upvalue 'nameOf'
    main.lua: in upvalue 'eachArray'
    main.lua: in upvalue 'refreshSpellNames'
```

- UE4SS 对游戏 `FName` 调 `ToString` 会抛 **C++ 异常**，该异常**无法被 Lua `pcall` 捕获**（traceback 直接穿过 pcall）。
- 抛在 hook 回调里时会穿过 hook trampoline → 栈被破坏 → `UE4SS.dll+0x6C328F` 访问违例。
- v1.4 每次 `IsUnlocked` 都打印锁名，读档瞬间 FName 表正在重建 → 崩前日志出现多行乱码。

修复：v1.5 钩子内完全不读参数；v1.6 移除 apply/诊断路径里所有 FName/FString 转换，只读整数计数。

### Bug B（v1.5 / v1.6，修于 v1.7）：非游戏线程调用对象表 API

- `LoopAsync` / `ExecuteWithDelay` 的回调运行在**非游戏线程**。
- Mod 在这些回调里周期性调用 `FindFirstOf("Biped_Player")`、`StaticFindObject(...)`、`obj:IsValid()`。
- 换图（level transition）时游戏线程正在重建对象表，异步线程遍历 `GUObjectArray` / name table → **use-after-free** → 同一个 `0x6C328F`。
- 证据吻合：v1.5 加 2 秒节流后，从「读档即崩」变成「换图时崩」。

修复（v1.7）：
1. 删除所有定时器里的原生调用（心跳只做 Lua 计数 + 打日志）。
2. 一切游戏 API 只在**游戏线程回调**里调用：`NotifyOnNewObject(Biped_Player)`、`IsUnlocked` 命中（每 1/50/500 次当 tick）、`ClientRestart`、`LoadMapPost`、控制台命令。
3. `getPlayer()` 不再搜索对象表，只返回已捕获且仍有效的 Pawn。
4. 换图时先丢弃旧 Pawn 引用（`state.player = nil`），避免对悬空对象 `IsValid`。

## 三、版本时间线

| 版本 | 变更 | 结果 |
|---|---|---|
| v1.4.0 | 冷却绕过 + 钩子内打印锁名 | 读档 2 秒后崩溃（Bug A） |
| v1.5.0 | 钩子不碰参数、去掉 post-hook、FindFirstOf 限频 2s | 稳定 7 分钟，进地下城时崩溃（Bug B） |
| v1.6.0 | 清除所有 FName 转换、只读整数计数 | 同样在进地下城时崩溃（Bug B） |
| **v1.7.0** | **删除定时器内原生调用，全部改到游戏线程回调** | 反复换图 / 读档 / 战斗均无崩溃 |

## 四、复现与自检方法

1. 启动游戏 → 进世界 → 在世界与地下城之间**反复进出 2~3 次**（本次崩溃的必现场景）。
2. 查看 `Win64\SpellUnlocker.log`，应出现：
   `LoadMapPost hook #n (player ref cleared)` / `pawn spawned ->` / `apply to pawn ... (re-apply)`，且 `heartbeat #n` 持续增长。
3. 若再出现 `Fatal Error`：保留 `Win64\ue4ss\crash_*.dmp`，用本仓库工具解析：

```bat
python tools\parse_minidump.py "C:\...\crash_YYYY_MM_DD_HH_MM_SS.dmp"
```

输出包含：异常码、出错地址 → 模块 + 偏移、访问类型与目标地址、崩溃线程 RIP/RSP、栈扫描（返回地址归属模块）。
据此可判断是「游戏本体 bug」「UE4SS 内部 bug」还是「Mod 代码问题」。
